HOW TO APPLY THESE RULES
=========================
1. Go to https://console.firebase.google.com/ → your project (swiftchain-827f2)
2. Firestore Database → Rules tab
3. Paste the rules below, replacing what's there → Publish

WHY THIS MATTERS
=================
Your Firebase apiKey/project config in assets/js/firebase-config.js being visible
in the page source is normal and expected for Firebase web apps — it is NOT a
secret key. The real security boundary is the Firestore Rules below. Without
rules like these, anyone can read/write ANY data in your database, including
other users' profiles, or approve their own fake reviews.

To make an account an admin: in Firestore, open the "users" collection, find
that user's document (its ID is their Firebase Auth UID), and add a field
role (string) = "admin".

RULES
=====

rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {

    // Reviews: anyone can submit a new review as "pending".
    // Only approved reviews are publicly readable.
    // Only admins can change status/featured or delete.
    match /reviews/{reviewId} {
      allow read: if resource.data.status == "approved"
                  || (request.auth != null
                      && get(/databases/$(database)/documents/users/$(request.auth.uid)).data.role == "admin");

      allow create: if request.resource.data.status == "pending"
                    && request.resource.data.featured == false
                    && request.resource.data.rating is int
                    && request.resource.data.rating >= 1
                    && request.resource.data.rating <= 5
                    && request.resource.data.name is string
                    && request.resource.data.name.size() > 0
                    && request.resource.data.name.size() < 80
                    && request.resource.data.comment is string
                    && request.resource.data.comment.size() > 0
                    && request.resource.data.comment.size() < 1000;

      allow update, delete: if request.auth != null
                    && get(/databases/$(database)/documents/users/$(request.auth.uid)).data.role == "admin";
    }

    // Users: a user can read/update their own profile.
    // Nobody can write their own "role" field (prevents self-promotion to admin).
    match /users/{userId} {
      allow read: if request.auth != null && request.auth.uid == userId;
      allow create: if request.auth != null && request.auth.uid == userId
                    && !("role" in request.resource.data);
      allow update: if request.auth != null && request.auth.uid == userId
                    && request.resource.data.role == resource.data.role;
    }

    // Default deny everything else — add explicit rules for any other
    // collection your dashboard/student-portal pages use (courses,
    // signals, assignments, etc.) before relying on this in production.
    match /{document=**} {
      allow read, write: if false;
    }
  }
}

ALSO CHECK: your Realtime Database (databaseURL in firebase-config.js) has its
own separate security rules under Realtime Database → Rules — lock that down
the same way if you're using it.
